## Change

- Represent the 21 former string fields reachable from `ServiceDiscoveryResponse`
  as `bytes`, retaining field numbers/cardinality and length-delimited wire type.
  Covers legacy HU metadata, `HeadUnitInfo`, Bluetooth address, vendor name and
  package list, and Wi-Fi BSSID. Other protocol strings remain unchanged.
- Adapt developer-mode setters, vendor matching/injection and HU Bluetooth
  injection to generated byte APIs. Configured overrides still intentionally
  replace their selected fields.
- Decode at the presentation boundary only. Valid UTF-8 retains existing text;
  invalid bytes show `non-UTF8[hex]` without guessing EUC-KR. Profile hashing uses
  this distinct representation instead of replacement characters. Diagnostic
  HTTP SDR JSON retains readable text for former string fields; unrelated bytes
  keep protobuf base64 encoding.
- Remove SSID/password from the ordinary Bluetooth parameter log. Suppress raw
  `WifiInfoResponse` hex in the optional sniffer, including malformed responses,
  because hex also exposes the WPA key. This is a targeted fix, not a full audit
  of every diagnostic/private log.

Preservation concerns **metadata field values**, not a promise that an entire
protobuf message is byte-for-byte identical after serialization. Protobuf can
normalize field ordering or duplicate singular fields. This does not transcode
bytes into valid UTF-8 for Android; original HU octets remain unchanged unless
deliberately overridden. Phone acceptance after SDR edits still needs testing.
